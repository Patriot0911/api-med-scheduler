# Команди

- Користувач тримає `npm run start:dev` (`nest --watch`, порт 3001) у своєму терміналі; `npm run build` перезаписує той самий `dist/`.
- Під час роботи типи перевіряй `npx tsc --noEmit -p tsconfig.json`.
- `npm run build` дозволено без згоди, але як **фінальну перевірку** наприкінці задачі (повна компіляція, як у CI й Docker), а не після кожної правки. Якщо порт 3001 зайнятий (`lsof -i :3001`) — у підсумку скажи, що watcher міг впасти й потребує перезапуску.
- Не запускати без попередження й згоди: `migration:generate`, `migration:run`, `migration:revert`, `seed:run` (працюють з БД). Міграцію пиши руками — dev-сервер застосує її сам (`migrationsRun: true`).
- `npm run lint` — `eslint --fix` по всьому `src`, `npm run lint:check` — те саме без виправлень (як у CI); код чистий, тож обидва безпечні. Швидкий лінт своїх файлів: `npx eslint <files>`. Prettier у проєкті немає, форматування — правила `@stylistic` в ESLint.
- Живу перевірку роби на вже запущеному сервері (`http://localhost:3001/api`, Swagger `/api/docs`). Ізольований запуск — `APP_PORT=<вільний> node dist/main.js` у фоні з обов'язковим завершенням після.
- `docker compose down -v` і будь-яке очищення БД — лише на пряме прохання.
